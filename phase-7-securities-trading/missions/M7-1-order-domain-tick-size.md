# M7-1 주문 도메인과 호가 단위

> 가이드 수준: L3 · 예상 시간: 5~6h · 선행: M6-8

## 목표
이 미션을 끝내면 다음을 할 수 있다.
- 호가단위 7개 구간의 경계 가격(1,999 / 2,000 / 2,001 등)이 유효한지 무효한지 파라미터화 테스트로 보여준다
- 기준가격에서 상한가·하한가를 계산하고, 호가단위 끝수 처리(상한 내림·하한 올림) 결과를 손 계산 값과 일치시킨다
- 주문 상태 전이표에 없는 전이를 시도하면 예외가 나고 주문 상태가 바뀌지 않는다는 것을 테스트로 보여준다
- 주문 검증 실패 사유를 `RejectReason` 하나로 돌려주는 검증기를 만든다

## 배경
호가단위에 맞지 않는 가격(예: 20,010원)이 호가창에 들어가면 같은 가격대에 표시할 수 없는 주문이 생기고, 그 주문은 체결 순서를 정할 기준이 없어진다.
가격제한폭을 벗어난 주문은 거래소가 거부하므로, 증권사가 미리 거르지 않으면 고객은 "접수됐다가 거부되는" 주문을 받는다.
주문 상태를 아무 메서드에서나 바꿀 수 있으면 `FILLED` 주문이 다시 `CANCELLED`가 되고, 홀드 해제(M7-2)가 두 번 일어나 주문가능금액이 실제보다 늘어난다.
Phase 6에서 계좌 상태 머신으로 "허용된 전이만 일어난다"를 만들었다. 이 미션은 같은 방법을 주문에 적용하고, 그 위에 KRX 가격 규칙을 얹는다.

## 요구사항
이 미션은 순수 Java 도메인만 만든다. DB·Spring 빈은 M7-2에서 붙인다. 개념은 [README](../README.md) 2절, 4절을 먼저 읽는다.

1. **워크스페이스**: README "워크스페이스 만들기"대로 프로젝트를 만든다. 패키지 `lab.trading.domain.order`에 이 미션의 클래스를 둔다.
2. **기본 타입**: `OrderSide`(`BUY`, `SELL`), `OrderType`(`LIMIT`, `MARKET`), `OrderStatus`(`RECEIVED`, `PARTIALLY_FILLED`, `FILLED`, `CANCELLED`, `REJECTED`), `Market`(`KOSPI`, `KOSDAQ`). 가격과 수량은 `long`(원, 주)이다.
3. **종목**: `Instrument`는 종목코드(6자리 영문 대문자·숫자), 시장, 기준가격을 가진다. README의 종목 3개를 쓴다.
4. **`TickSizePolicy`**
   - 가격을 받아 그 가격이 속한 구간의 호가단위를 돌려준다. 구간표는 README 4절과 같다.
   - 가격이 호가단위의 배수인지 판정한다. 0 이하 가격은 무효다.
   - 경계: 가격이 구간 하한과 같으면 그 구간에 속한다(2,000원은 5원 구간, 500,000원은 1,000원 구간).
5. **`PriceLimitPolicy`**
   - 기준가격으로 상한가·하한가를 계산한다. 끝수 처리는 이 미션의 규칙: 상한가는 `기준가격 × 1.3`을 그 값이 속한 구간의 호가단위로 내림, 하한가는 `기준가격 × 0.7`을 그 값이 속한 구간의 호가단위로 올림.
   - `기준가격 × 1.3`처럼 소수가 생기는 계산을 `double`로 하지 않는다. 정수 연산(`기준가격 × 13`을 10으로 나누는 식) 또는 `BigDecimal`을 쓴다.
6. **거래 시간**: `MarketHours`는 주입받은 `java.time.Clock`(Asia/Seoul)으로 접수 가능 여부를 판정한다. 이 미션의 규칙: 월~금 09:00:00 이상 15:20:00 미만만 접수 가능. 토·일은 불가. 공휴일은 M7-6의 `BusinessCalendar`에서 다루고 이 미션에서는 무시한다.
7. **`Order`**
   - 필드: 주문 ID, 계좌 ID, 종목코드, `OrderSide`, `OrderType`, 지정가(시장가는 없음), 주문수량, 체결수량, 취소수량, 상태, 거부 사유, 접수 시각.
   - 미체결수량 = 주문수량 − 체결수량 − 취소수량. 불변식: 미체결수량 ≥ 0. 이 불변식을 깨는 호출은 예외를 던지고 상태를 바꾸지 않는다.
   - 상태를 바꾸는 방법은 `Order`의 메서드뿐이다(setter 금지). 메서드 이름은 직접 정한다.
8. **상태 전이표** (이 미션의 규칙). 표에 없는 전이는 `IllegalOrderStateException`을 던진다.

   | 현재 상태 | 사건 | 다음 상태 |
   |---|---|---|
   | (생성) | 검증 통과 | `RECEIVED` |
   | (생성) | 검증 실패 | `REJECTED` (거부 사유 저장, 체결·취소수량 0) |
   | `RECEIVED` | 일부 체결 (체결 후 미체결 > 0) | `PARTIALLY_FILLED` |
   | `RECEIVED`, `PARTIALLY_FILLED` | 체결 후 미체결 = 0 | `FILLED` |
   | `PARTIALLY_FILLED` | 추가 일부 체결 | `PARTIALLY_FILLED` |
   | `RECEIVED` (체결·취소 0) | 엔진 제출 실패 (M7-4 `ENGINE_BUSY`) | `REJECTED` (거부 사유 저장) |
   | `RECEIVED`, `PARTIALLY_FILLED` | 미체결 전량 취소 (사용자 취소, 시장가 잔량, 자기매매 방지) | `CANCELLED` (체결수량은 그대로 남는다) |
   | `FILLED`, `CANCELLED`, `REJECTED` | 모든 사건 | 예외 (종료 상태) |

   체결 수량이 0 이하이거나 미체결수량보다 크면 `IllegalArgumentException`을 던진다.
9. **`OrderValidator`**: 주문 요청(계좌 ID, 종목코드, 매수/매도, 유형, 가격, 수량)과 현재 시각을 받아 통과 또는 `RejectReason` 하나를 돌려준다. 여러 사유에 해당하면 아래 순서에서 먼저 걸린 사유를 돌려준다.

   | 순서 | `RejectReason` | 조건 |
   |---|---|---|
   | 1 | `MARKET_CLOSED` | 6번 규칙상 접수 불가 시각 |
   | 2 | `UNKNOWN_SYMBOL` | 등록되지 않은 종목코드 |
   | 3 | `INVALID_QUANTITY` | 수량 ≤ 0 또는 수량 > 1,000,000 (상한은 이 미션의 규칙) |
   | 4 | `INVALID_PRICE` | 지정가인데 가격 없음, 또는 시장가인데 가격 있음 |
   | 5 | `INVALID_TICK` | 지정가 가격이 0 이하이거나 호가단위의 배수가 아님 |
   | 6 | `PRICE_OUT_OF_LIMIT` | 지정가 가격이 하한가 미만 또는 상한가 초과 (상·하한가와 같은 가격은 통과) |

   M7-2에서 `INSUFFICIENT_CASH`, `INSUFFICIENT_QUANTITY`, M7-4에서 `ENGINE_BUSY`를 같은 열거형에 추가한다.

## 직접 작성할 테스트 시나리오
`docs/test-scenarios/M7-1.md`에 표(# / 준비 / 실행 / 기대 결과)를 쓰고 리뷰를 받은 뒤 구현한다. **최소 30개**. 반드시 포함할 경우:

1. 호가단위 판정: 1,999(유효) / 2,000(유효) / 2,001(무효) / 4,995(유효) / 5,000(유효) / 19,990(유효) / 20,000(유효) / 20,010(무효) / 49,950(유효) / 50,000(유효) / 199,900(유효) / 200,000(유효) / 499,500(유효) / 500,000(유효) / 500,500(무효) / 501,000(유효) / 0(무효) / -10(무효)
2. 상·하한가 계산 (기대값은 이 미션의 끝수 규칙으로 계산한 값):

   | 기준가격 | 상한가 | 하한가 |
   |---|---|---|
   | 10,000 | 13,000 | 7,000 |
   | 70,000 | 91,000 | 49,000 |
   | 15,430 | 20,050 | 10,810 |
   | 3,333 | 4,330 | 2,335 |
   | 1,999 | 2,595 | 1,400 |
   | 385,000 | 500,000 | 269,500 |

   계산식: 15,430 × 1.3 = 20,059 → 20,000 이상 구간(50원) 내림 → 20,050. 15,430 × 0.7 = 10,801 → 10원 올림 → 10,810. 385,000 × 1.3 = 500,500 → 1,000원 구간 내림 → 500,000. 1,999 × 0.7 = 1,399.3 → 1원 올림 → 1,400.
3. 가격제한폭 경계 (`A00002`, 기준가격 10,000): 13,000 통과 / 13,010 `PRICE_OUT_OF_LIMIT` / 7,000 통과 / 6,990 `PRICE_OUT_OF_LIMIT`
4. 거래 시간 (2026-11-09 월요일 기준): 08:59:59 `MARKET_CLOSED` / 09:00:00 통과 / 15:19:59 통과 / 15:20:00 `MARKET_CLOSED` / 2026-11-14 토요일 10:00 `MARKET_CLOSED`
5. 사유 우선순위: 15:30에 들어온 수량 0 주문은 `MARKET_CLOSED`, 장중에 들어온 수량 0·가격 20,010 주문은 `INVALID_QUANTITY`
6. 수량 경계: 0, -1, 1, 1,000,000, 1,000,001
7. 시장가에 가격 10,000을 넣은 주문 → `INVALID_PRICE`
8. 상태 전이: 수량 10 주문에 4 체결 → `PARTIALLY_FILLED`(미체결 6), 이어서 6 체결 → `FILLED`, `FILLED`에 취소 → 예외이고 상태·수량 그대로
9. 수량 10 주문에 4 체결 후 취소 → `CANCELLED`, 체결 4·취소 6·미체결 0
10. 미체결 6인 주문에 7 체결 → `IllegalArgumentException`, 수량 그대로

## 제약
- 가격·수량에 `double`, `float` 금지 — 1.3배·0.7배 계산에서 2진 부동소수점 오차가 끝수 처리를 바꾼다.
- `Order`에 public setter 금지 — 상태 전이표를 우회하는 경로가 생긴다.
- `LocalDateTime.now()` 직접 호출 금지 — 시간 경계 테스트를 할 수 없다. `Clock`을 주입한다.
- 이 미션에서 Spring 애노테이션(`@Entity`, `@Component`)을 붙이지 않는다. JPA 매핑은 M7-2에서 한다.
