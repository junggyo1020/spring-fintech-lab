# 커리큘럼 문서 검증

학습자는 문서를 정답으로 믿고 따라간다. 문서의 틀린 기대값 하나가 학습자에게 "내 코드가 틀렸다"는 잘못된 결론을 주고,
틀린 개념 설명 하나가 면접에서 틀린 답으로 이어진다. 그래서 검증은 "있는지 확인"이 아니라 "맞는지 재현"으로 한다.

## 절차

### 1단계: 자동 검사
```bash
python3 .claude/skills/curriculum-verification/scripts/check_docs.py <대상 경로>
```
ERROR(깨진 링크, 미션 구조, details 태그, 미션 표 누락)는 전부 고친다. WARN(추상 표현)은 한 줄씩 판단한다.

### 2단계: 재현 검증 (사람이 읽어야 하는 부분)

| 대상 | 검증 방법 |
|---|---|
| 테스트 시나리오의 숫자 | `python3 -c "from decimal import Decimal ..."`로 다시 계산. 반올림 모드(`ROUND_DOWN`, `ROUND_HALF_EVEN`, `ROUND_HALF_UP`)를 문서와 같게 맞춘다 |
| 제공된 코드 조각 (테스트 틀, 설정 파일) | 머릿속으로 실행한다. 스레드 풀 크기와 래치 개수, 예외 처리 경로, 무한 대기 가능성을 따라간다. 의심되면 scratchpad에서 `javac`/`jshell`로 실행한다 |
| API 동작 서술 (Java, Spring, JPA, MySQL) | 공식 문서(Javadoc, Spring Reference, MySQL Reference Manual)로 확인. 버전에 따라 다르면 버전 명시 여부 확인 |
| 버전·지원 종료일 | 웹 검색 2개 이상 출처로 교차 확인 |
| 금융 규칙 (세금, 호가, 결제일, 회계) | `.claude/skills/fintech-domain-facts/SKILL.md`와 대조, 없으면 공식 기관(국세청, KRX, 법령정보센터) 자료로 확인 |
| 명세 완결성 | 경계값(0, 음수, null, 같은 계좌, 동시 요청, 자정·월말·윤년) 동작이 정해졌는지. 학습자 두 명이 다른 테스트를 쓸 수 있는 문장을 찾는다 |
| 미션 간 정합성 | `docs/curriculum-map.md`의 선행·만드는 것·클래스 이름과 대조. 앞 미션에서 만들지 않은 클래스를 뒤 미션이 전제하면 오류 |
| 실행 시간 | 제시된 작업량으로 테스트를 돌릴 때 걸리는 시간을 계산 (예: 100ms × 10,000건 ÷ 스레드 1개 = 1,000초) |

### 3단계: 보고서

`_workspace/{phase}_{verifier}_findings.md`에 아래 형식으로 쓴다.

```markdown
| # | 심각도 | 파일:줄 | 문제 | 근거 (계산식/출처 URL/재현 결과) | 수정안 (바꿀 문장 그대로) |
```

심각도 기준:
- **오류**: 따라 하면 테스트가 멈추거나, 틀린 기대값이 나오거나, 틀린 개념을 배운다
- **모호**: 학습자마다 다르게 구현할 수 있다
- **표현**: 추상 표현, 오타, 서식

근거가 없는 지적은 보고서에 넣지 않는다. 확인하지 못한 의심은 "확인 필요" 열로 분리한다.

### 4단계: 수정
수정 권한을 받은 경우, 오류·모호 항목을 직접 고친 뒤 1단계 스크립트를 다시 실행해 결과를 보고서 끝에 붙인다.
수정은 해당 문장만 바꾼다. 문서 전체를 다시 쓰지 않는다.
