# 미션 문서 작성

이 레포는 정답 코드 없이 문서만으로 학습자가 Java/Spring 백엔드를 혼자 구현할 수 있게 만드는 것이 목적이다.
문서가 모호하면 학습자는 무엇을 만들어야 하는지 모른 채 멈추거나, 틀린 것을 맞다고 믿고 넘어간다.
그래서 모든 문장은 "학습자가 이 문장만 보고 코드를 짤 수 있는가"를 기준으로 쓴다.

## 작성 전에 읽을 파일

1. `docs/curriculum-map.md` — 미션 이름, 선행 관계, 만드는 것, 가이드 수준, 기준 버전. 여기와 다르게 쓰지 않는다.
2. 해당 Phase의 `README.md`와 이전 Phase의 README·마지막 종합 미션 — 학습자가 이미 만든 클래스 이름을 이어 쓰기 위해
3. `references/mission-template.md` — 미션 문서 구조
4. `references/phase-readme-template.md` — Phase README 구조
5. 금융 규칙(세금, 호가단위, 결제일, 복식부기)이 나오면 `.claude/skills/fintech-domain-facts/SKILL.md`

## 규칙

### 1. 구체적으로 쓴다
추상 표현은 학습자가 완료 여부를 판단할 수 없게 만든다. 아래처럼 바꾼다.

| 쓰지 않는 표현 | 바꾸는 방법 |
|---|---|
| "충분히 빠르다", "지연되지 않는다" | "p99 200ms 이하", "C→D 이체가 100ms 안에 끝난다" |
| "대량", "수천 개", "초당 수만 건" | "스레드 1,000개", "초당 5,000건" |
| "이해한다", "익힌다", "체감한다" | "~를 테스트로 보여준다", "~의 차이를 표로 기록한다" |
| "적절히 처리", "알맞게" | 처리 규칙 자체를 쓴다 ("예외 X를 던지고 잔액은 바뀌지 않는다") |
| "그때그때", "가볍게 훑고" | 조건과 범위를 쓴다 ("README 1~3절만 읽고") |
| 가운뎃점(`\u00b7`), 긴 줄표(`\u2014`), 이모지 | 쉼표, 괄호, 줄 나누기, 표에서는 단어(충족, 미충족) |
| 근거 없는 평가("훌륭한", "깔끔한"), 추측("~것 같다"), 내용 없는 연결어("결론적으로") | 확인한 사실과 수치. 전체 목록은 `.claude/skills/mission-review/references/writing-rules.md` 3절 |

`scripts`는 `.claude/skills/curriculum-verification/scripts/check_docs.py`에 있다. 작성 후 실행해 경고를 0개로 만든다. 경고가 정당한 사용(예: 인용, 코드 안 문자열)이면 그대로 두고 보고에 이유를 적는다.

### 2. 경계값을 모두 정한다
0, 음수, `null`, 빈 문자열, 같은 계좌 이체, 동시에 같은 요청, 시간 경계(자정, 월말, 윤년)를 요구사항에서 정한다.
정하지 않으면 학습자마다 다른 테스트가 나오고 리뷰 기준이 사라진다.

### 3. 기대값은 직접 계산한다
테스트 시나리오의 숫자는 Python `decimal` 등으로 계산해 확인한다. 구현 코드로 기대값을 만들면 테스트가 아무것도 검증하지 못한다는 원칙을 문서도 지킨다.
계산이 3단계 이상이면 표 아래 계산식을 적는다.

### 4. 정답 코드를 주지 않는다
학습자가 직접 설계하고 타이핑해야 실력이 오른다. 제공해도 되는 것은 가이드 수준별로 다르다.
- L1: 시그니처, 테스트 뼈대(given/when/then 주석), 설정 파일(build.gradle.kts 등)
- L2: 핵심 인터페이스 시그니처, 설정 파일
- L3: 설정 파일의 의존성 좌표만
설정 파일과 인프라 명령어(docker run 등)는 학습 목표가 아니므로 전부 제공해도 된다.

### 5. 버전에 따라 달라지는 동작은 버전을 적는다
예: "JDK 21에서는 `synchronized` 안의 블로킹이 가상 스레드를 캐리어에 고정한다(JDK 24에서 JEP 491로 해소)".
Spring Boot 4.x는 Jackson 3(`tools.jackson` 패키지)을 쓴다. 3.x 기준 블로그 코드를 그대로 옮기지 않는다.

### 6. 확인한 사실만 쓴다
버전·세율·법규·API 동작을 쓸 때 확실하지 않으면 공식 문서로 확인한다. 확인하지 못했으면 "이 미션의 규칙으로 정한다"고 명시하고 실제 제도처럼 쓰지 않는다.

### 7. 미션 간 연결
각 미션의 "배경"에 이전 미션과의 연결을 한 문장, "생각해볼 질문"에 다음 Phase로 이어지는 질문을 하나 넣는다.
학습자가 "왜 이걸 지금 배우는가"를 알면 중간에 멈추지 않는다.

## 출력

- 미션 파일 경로: `phase-{P}-{slug}/missions/M{P}-{N}-{slug}.md` (slug는 영문 소문자와 하이픈)
- Phase README의 미션 표 링크와 파일명이 일치해야 한다.
- 작업이 끝나면 `python3 .claude/skills/curriculum-verification/scripts/check_docs.py phase-{P}-*` 결과를 보고에 붙인다.
