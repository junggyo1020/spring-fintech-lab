# 주차별 로드맵 (27.5주)

주 10~15시간 기준이다. 아래 "예상 시간"은 각 미션 문서의 예상 시간을 합한 범위이고, Phase README의 주차별 계획과 같은 값이다.
한 주에 15시간을 쓰고도 미션이 남으면 남은 부분을 다음 주로 넘긴다. 미션을 건너뛰지 않는다.
각 주의 마지막 학습일(주말 3시간)은 PR 리뷰 반영, 그 주 TIL 다시 읽기, [레벨 진단](self-check.md) 해당 항목 답하기에 쓴다.

## Phase 완료 기준 요약

다음 Phase로 넘어가기 전에 각 Phase README의 "완료 기준"을 모두 체크한다. 아래는 각 Phase의 대표 기준 하나다.

| Phase | 대표 완료 기준 |
|---|---|
| 0 | PR을 열면 GitHub Actions `ci` 워크플로가 초록 체크로 끝나고, 그 PR을 main에 머지했다 |
| 1 | `./gradlew test jacocoTestReport jacocoTestCoverageVerification`이 `BUILD SUCCESSFUL`로 끝난다 (도메인 패키지 라인 커버리지 90% 이상, M1-5) |
| 2 | M2-7의 반복 지정 시나리오가 `@RepeatedTest(100)`에서 100회 모두 통과한다 |
| 3 | M3-5 self-invocation 재현 테스트가 "감사 로그 0건"을, 고친 2가지 버전 테스트가 "감사 로그 3건"을 단언하며 모두 통과한다 |
| 4 | 모든 오류 응답이 `application/problem+json`이고 `type`, `title`, `status`, `detail`, `instance`, `code` 6개 필드를 가진다 (M4-8 테스트로 확인) |
| 5 | `@Transactional`만 붙인 출금이 lost update를 막지 못함을 M5-8 테스트로 보여주고, 비관적 락·낙관적 락·조건부 UPDATE 비교표를 남긴다 |
| 6 | M6-4 동시성 테스트(핫 계좌 입금 1,000건, 랜덤 이체 10,000건) 후 Phase 6 불변식 INV-1(분개별 Σ차변 = Σ대변), INV-2가 성립한다 |
| 7 | 명령 10만 건 실행 후 전체 재생과 스냅샷+꼬리 재생으로 복구한 호가창 해시가 원본과 같다 (M7-8) |
| 8 | `docs/load-test-report.md`에 변경 1가지씩 최소 3회의 전후 측정 행이 있고, 마지막 행이 "500 req/s, p99 < 300ms, 에러율 < 0.1%"를 만족하거나 못한 이유를 지표 값으로 적었다 |
