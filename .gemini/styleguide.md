# spring-fintech-lab 리뷰 가이드

## 리뷰 언어와 형식
- 모든 리뷰, 요약, 댓글 답변은 한국어로 쓴다.
- 이 레포는 학습자가 정답 코드 없이 미션을 직접 구현하는 학습용 레포다. 수정된 코드 블록이나 suggestion 블록을 쓰지 않는다.
- 지적 1건은 `파일:줄` + 관찰한 사실 + 학습자가 스스로 답을 찾을 질문 1개로 쓴다.
  예: "잔액 검사와 차감 사이에 다른 스레드가 끼어들 수 있다. 두 스레드가 동시에 이 줄에 도착하면 각각 어떤 잔액을 읽는가?"
- 미션 요구사항은 PR 본문의 "미션 문서" 링크에 있다. 요구사항에 없는 기능 추가를 제안하지 않는다.

## 우선순위 (높은 순)
1. 정합성: 돈이 생기거나 사라지는 경로, 예외 발생 시 상태가 일부만 바뀌는 경로
2. 불변식: 잔액 >= 0, 차변 합 = 대변 합 같은 규칙을 객체 내부에서 지키는가, 외부 코드로 깨뜨릴 수 있는가
3. 동시성: 공유 가변 상태가 무엇이고 무엇으로 보호하는가, check-then-act 구간이 원자적인가
4. 금액 타입: `double`/`float`로 금액을 다루는가, `BigDecimal`의 `equals`/`compareTo` 혼동, 나눗셈의 `RoundingMode` 누락
5. 테스트: 기대값을 구현 코드로 계산하지 않았는가, 경계값(0, 정확히 잔액, 잔액+1)이 있는가, `@DisplayName`에 미션 시나리오 번호(`#N`)가 있는가, 동시성 테스트가 `await` 결과를 단언하는가

## 지적하지 않는 것
- `static` 필드 사용 자체
- `til/` 파일의 문체와 형식 (기술적으로 틀린 설명만 지적한다)
- import 순서, 공백 같은 포매팅
