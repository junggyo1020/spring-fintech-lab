# M1-5 [종합] 콘솔 뱅킹 애플리케이션

## 목표
M1-1 ~ M1-4의 도메인을 조합해 **콘솔에서 동작하는 은행 프로그램**을 만든다.
UI(입출력)와 도메인 로직을 **분리**하는 연습이 핵심이다.

## 기능

```
===== Fintech Lab Bank =====
1. 계좌 개설
2. 입금
3. 출금
4. 이체
5. 거래내역 조회 (기간)
6. 거래 취소
7. 이자 계산 (예상 이자 + 세후)
8. 계좌 정지/해제/해지
0. 종료
선택>
```

- 잘못된 입력(문자, 음수, 없는 메뉴)에 프로그램이 죽지 않는다
- 도메인 예외는 사용자 친화적 메시지로 출력한다 (예: `잔액이 부족합니다. (현재 잔액: KRW 5,000)`)
- 계좌번호는 자동 발급 (`110-` + 랜덤 4자리 + `-` + 순번 4자리 등, 중복 없이)

## 구조 요구사항

```
lab.bank
├── (M1-1~4 도메인)
├── application/
│   └── BankService           # 유스케이스. 콘솔을 전혀 모른다
└── console/
    ├── BankConsoleApp        # main
    ├── InputView             # Scanner 래핑
    ├── OutputView            # 출력 포맷
    └── MenuController        # 입력 → BankService 호출 → 출력
```

- `BankService`는 `System.in`/`System.out`을 **절대** 참조하지 않는다
- `InputView`를 인터페이스로 만들면, 테스트에서 가짜 입력을 넣어 `MenuController`를 테스트할 수 있다
- `Clock`, `AccountNumberGenerator`, `InterestPolicy`는 생성자로 주입 → **"직접 만든 DI"**
  (Phase 3에서 이 부분을 Spring이 대신해주는 걸 보게 된다)

## 검증 기준
- [ ] `BankService` 단위 테스트: 모든 유스케이스 + 실패 케이스
- [ ] `MenuController` 테스트: 가짜 InputView로 "개설 → 입금 → 출금 → 조회" 시나리오
- [ ] `main`을 실행해서 직접 10분간 써보고, 발견한 버그를 테스트로 먼저 재현한 후 수정
- [ ] 전체 테스트 커버리지 확인 (IntelliJ "Run with Coverage") — 도메인 패키지 90% 이상
