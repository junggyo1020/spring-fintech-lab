# M1-4 이자 계산기와 반올림 정책

## 배경
이자 계산은 "연이율 × 잔액"처럼 단순해 보이지만, 실제로는
**일할 계산, 연 일수 기준(365/366), 절사/반올림 시점, 세금**이 모두 정책이다.
정책이 바뀌어도 코드를 크게 고치지 않도록 **전략 패턴**으로 설계한다.

## 요구사항

### `InterestPolicy` (인터페이스)
```java
public interface InterestPolicy {
    Money calculate(Money principal, BigDecimal annualRate, LocalDate from, LocalDate to);
}
```
- `from` 포함, `to` 미포함 (`[from, to)`) 일수로 계산

### 구현체 1: `SimpleDailyInterestPolicy` (단리, 일할 계산)
- 이자 = 원금 × 연이율 × (일수 / 365)
- 결과는 **원 단위 절사** (`RoundingMode.DOWN`) — 은행 예금 이자는 보통 절사

### 구현체 2: `ActualDaysInterestPolicy` (실제 연 일수 기준)
- 윤년이면 366일 기준
- 기간이 해를 넘어가면(예: 2027-12-15 ~ 2028-01-15) **해마다 나눠서** 계산 후 합산
- 최종 결과만 절사 (중간 결과는 절사하지 않음 — scale 10 정도로 유지)

### 구현체 3: `MonthlyCompoundInterestPolicy` (월복리)
- 매월 말일에 이자가 원금에 합산된다고 가정
- 각 월 이자는 원 단위 절사 후 원금에 합산

### `TaxCalculator`
- 이자소득세 15.4% (소득세 14% + 지방소득세 1.4%)
- 세금은 **10원 미만 절사**
- `AfterTaxInterest calculate(Money interest)` → `record AfterTaxInterest(Money gross, Money tax, Money net)`
- `gross == tax + net`이 항상 성립

<details>
<summary>힌트 2: 중간 계산 정밀도</summary>

`3.5% × 30 / 365`를 먼저 계산해서 반올림하면 오차가 커진다. 곱셈을 먼저 다 하고 나눗셈을 마지막에, 그리고 마지막에 한 번만 반올림.
`Money.times`만으로 부족하면 `BigDecimal`로 계산 후 마지막에 `Money`로 만드는 것도 방법이다. 어떤 게 더 좋은 설계일까?
</details>
