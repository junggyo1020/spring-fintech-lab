# Phase 8 — 분산 환경 & 운영 수준 (3주+)

## 목표
단일 애플리케이션·단일 DB에서 벗어나, **서비스가 나뉘었을 때의 정합성**과 **운영 가능성(관측·부하·장애)** 을 다룬다.

## 주제
| 주 | 주제 |
|---|---|
| 1주 | 계좌 서비스 / 주문 서비스 분리, Kafka 기초(파티션, 컨슈머 그룹, 오프셋, 순서 보장 범위), **Transactional Outbox** 패턴, 멱등 컨슈머 |
| 2주 | **Saga** (주문 → 예수금 홀드 → 체결 → 정산, 실패 시 보상), 오케스트레이션 vs 코레오그래피, 최종 일관성 모니터링 |
| 3주 | Micrometer + Prometheus + Grafana 대시보드, OpenTelemetry 분산 트레이싱, k6 부하 테스트, 병목 분석 리포트, 장애 주입(카오스) 실험 |

## 미션 (상세 문서는 Phase 7 완료 후 작성)
- **M8-1 이중 쓰기 문제 재현**: DB 커밋 후 Kafka 발행 실패 / Kafka 발행 후 DB 롤백 → 데이터 불일치 재현
- **M8-2 Outbox 구현**: 같은 트랜잭션으로 outbox 테이블 기록 → 릴레이가 발행, 중복 발행에 대비한 멱등 컨슈머
- **M8-3 Saga**: 증권 주문-계좌 서비스 간 Saga, 각 단계 실패 주입 테스트
- **M8-4 관측성**: 이체 TPS, 실패율, 락 대기 시간, 커넥션 풀 사용률 대시보드
- **M8-5 부하 & 튜닝 리포트**: 목표 TPS 설정 → 측정 → 병목(DB 락? 커넥션 풀? GC?) 식별 → 개선 → 재측정
- **M8-6 포트폴리오 정리**: 전체 아키텍처 다이어그램, 핵심 설계 결정(ADR), 트러블슈팅 사례 3개

## 완료 기준
- [ ] "DB 트랜잭션과 메시지 발행을 원자적으로 할 수 없다"는 문제와 Outbox의 해법을 설명
- [ ] 메시지가 중복·순서 뒤바뀜으로 와도 결과가 같다
- [ ] 부하 테스트 결과와 근거 있는 개선 리포트를 가지고 있다
